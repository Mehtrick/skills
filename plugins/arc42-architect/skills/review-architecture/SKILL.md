# Quality Review

For repository work, follow the [project architecture index workflow](../document-architecture/references/architecture-index.md) to verify relevant entries, find missing locations, and confirm uncertain paths before editing.

1. Establish scope and read relevant sections, the project's glossary, quality goals, and architectural decisions. Check structural integrity, including include directives, links, headings, numbering, and stable IDs.
2. Check terminology and quality attributes against the project's definitions. Use the [bundled quality model reference](references/quality-model.md) when appropriate. Check that quality scenarios are measurable and evidence in a quality tree traces to actual goals, scenarios, or accepted ADRs.
3. Distinguish confirmed findings from questions and document the effect of each consequential issue. Cite the artifact and location, rationale, and a concrete correction. If asked to validate section 1, check that goals are distinct, architecture-relevant, prioritized, and grounded in stakeholder expectations.
4. For a review-only request, report the findings in chat. When the review is part of drafting, resolve findings within the requested scope before finalizing and report any remaining gaps.
